01 · Why this exists

Learn the control layer, not a tool list

The curriculum is designed to produce defensible engineering judgment around consequential AI-agent workflows in regulated financial institutions.

The mission

Design, implement, test and challenge the control layer around consequential AI-agent workflows.

Banking operations + AI systems + institutional controls + architecture
  • Identity lives inside Permission.
  • Lifecycle and change cut across Evidence and Power.
  • The goal is not to become a generic AI engineer.

Benchmark, not dependency

DBS is the benchmark because its public direction is unusually close to this capability: agent control-plane work alongside Data & AI Risk, Technology Risk, Model Validation and Risk Enterprise Architecture.

But the competence stays portable if the employer, role or market changes.

  • Primary experience anchor: branch banking operations, retail credit, administrative/control workflows, maker-checker, exceptions, escalation and audit-sensitive operations.

05 · How to execute

The 10-day book system

You do not execute the whole curriculum directly. You execute the current ten-day book, then use the gate to decide what happens next.

Every book carries a contract

  • Book ID and capability
  • Why this exists in the architecture
  • Exact source section and prerequisite
  • Source time ceiling and done condition
  • Proof, low-energy version and prohibited assistance
  • Low-energy work stays on the same current capability; it is not permission to switch to an easier topic
  • Fixed gate criteria and blank-file variation
  • Build Test and Defense Test where applicable
  • Unlock evidence and controls/Cx-control-statement.md
  • Exit gate and artifact evidence
  • Known limitations and parking-lot items

Use AI without outsourcing comprehension

Write your hypothesis first. Let the first AI pass ask questions or provide hints. If substantial assistance occurs, reproduce from a blank file and then solve a variation.

Source covenant: one primary source, one reference source and one artifact objective per book.

Execution: Need → minimum reading → attempt → build → fail → diagnose → rebuild → explain → commit.

Generated code does not count as learned capability.

06 · Retrieval practice

Review deck

Answer each prompt aloud before revealing the suggested answer. A strong answer names the boundary, the authority, the evidence and the recovery path.

Graduation standard: You are ready when you can explain the system to a skeptical reviewer, show working evidence, defend architecture decisions, handle failure and say clearly what the system still cannot prove.
